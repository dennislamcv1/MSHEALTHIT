TKT-3103 (EHR access portal returning "Service unavailable") was the hardest ticket to classify. It arrived during an active Microsoft Entra ID sign-in event and involved the same EHR portal named in TKT-3101, so it looked like part of the platform cluster, yet it was the only ticket with no matching Service Health event, and a missing event does not prove the platform is healthy. I resolved this with the cloud verification checklist: sign-in completed and Teams worked for the same users, which ruled out the Entra event, and applying the PaaS shared-responsibility model to the supplied architecture placed the failing step in the customer-managed portal application on Azure App Service. Because Tier 1 cannot see application or hosting diagnostics, I labeled it a local issue with an undetermined cause and warm-transferred it to Tier 2 Engineering with a specific ask: find why the portal fails after successful sign-in, and open a Microsoft support case if platform involvement is found.
